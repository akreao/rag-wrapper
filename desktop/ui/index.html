      Publish client patch
      
      
      Players' patchers download new patches from the account portal. Put the files players need in the client files folder, laid out like the game client's own folder:
      
      
        
        
      • rag-wrapper.exe: the patched client, which the patcher's Play button starts.
        • 
        
      • data/: sprites, textures, maps and other GRF content, packed into rag-wrapper.grf. The patch also writes the client's DATA.INI so it reads that GRF first.
        • 
        
      • Anything else, such as System/ files, is copied into the client folder as is.
        • 
        
      • Pre-Renewal/ and Renewal/: files for one game mode only, such as translation additions, laid out the same way. Players get the server's current mode's files, which replace shared files of the same name. After a mode switch, publish a patch to swap them.
        • 
              
      • Mods that are on can add their own client files, from their client/ folder, laid out the same way. They're added after this folder, in load order: a mod's file replaces one of the same name, except that the entries of Lua tables (.lub, .lua files such as System/itemInfo.lua) are merged.
        • 
      
      
      
      Only hand out the patched exe, your own custom content and your own translation additions: never the full client or llchrisll's translation, which players install themselves.

            Mods
            
      
            Server-side custom content: NPC scripts and changes to rAthena's databases. Add a mod by copying its folder into the mods folder, one folder per mod:
            
      
              
        
            • npc/: NPC scripts (.txt), loaded after rAthena's own.
              • 
        
            • db/: database files named like rAthena's db/import files (item_db.yml, mob_db.yml, ...). Files in db/pre-re/ or db/re/ only load in that game mode.
              • 
        
            • client/: files for the players' game client, such as sprites or System/itemInfo.lua, laid out like the client folder. They go out with the next client patch, published on the Client patch screen.
              • 
      
            
      
            The mods that are on load from top to bottom, so when two change the same entry the lower one wins; the arrows change the order.
            
      
            
        
        
      
            
      
            
    
            
    
            
      
            
        The running server was built before mods existed, so it ignores them. Rebuild the server to load mods, then restart it.
        
      
            
      
            
        Some changes wait for the game servers to restart, which disconnects everyone. When a mod's database files load for the first time, the database is backed up first.
