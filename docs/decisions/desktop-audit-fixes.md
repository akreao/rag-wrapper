# Desktop app audit fixes

The desktop app's findings from the audit of 2026-10-16, fixed in one PR.

- **`.env` is written atomically and readable by its owner only.** Every save writes `.env.tmp` with mode 0600, syncs it to disk and renames it over `.env`, so a full disk or a crash can't leave `.env` empty and lose the database passwords. First-run setup writes the example the same way, so the generated passwords are never in a file other users can read.
- **One `.env` edit at a time.** Every load, change and save of `.env`, from a screen or from a running task, holds one lock, so two edits can't save over each other.
- **`.env` is read the way Compose reads it.** A key set twice takes its last line, and the app changes that line. An unquoted value ends at ` #`, so `PRERE=no  # renewal` reads as Renewal.
- **Docker calls run off the main thread and give up after 60 seconds.** The overview, the service status the dashboard polls every 3 seconds, starting a task and first-run setup no longer stop the window from drawing while Docker answers. A Docker call that takes longer than 60 seconds is killed and reported ("Is Docker stuck?"). The few that can take longer have their own limit: the mod clash check 5 minutes, the restore test's table check an hour. Closing the app waits up to 2 minutes for `docker compose down`, then closes anyway.
- **One copy of the app at a time.** Opening the app again brings the open window forward (`tauri-plugin-single-instance`). A second copy used to copy the stack files again under a running build, and closing either window stopped the server for both.
- **A mod's client files can't link outside the mod.** A link in a mod's `client/` folder to a file outside that folder is left out of the client patch and listed as a problem, so a mod can't hand a file such as `~/.ssh` keys or `.env` to every player. Links in the client files folder are still followed: it's the admin's own folder, and a link there is how a translation's files can be handed out without copying them (Steven, 2026-10-16).
- **The Mods screen reads only the map server's new log lines.** The log since the map server last started is kept between reads, and each read asks Docker only for lines after the newest one it has. It used to fetch the whole log since the container was made every 5 seconds. Log rotation is in the Docker stack's own fix.
- **A Lua table a mod assigns twice gets one comma.** The merge used to write `,,`, which stops the client loading the merged file.
- **Backups are readable by their owner only.** The backups folder is 0700 and each dump 0600, as dumps hold every account's password hash and email. The app closes up an existing folder and its backups the next time it backs up or opens the folder.
- **Smaller hardening.** A backup name may only use lowercase letters, digits and `-` after its timestamp, so a restore can't reach a file outside the backups folder. The mod clash check never pulls an image (`--pull never`).
- **"This network only" (follow-up, after the stack's `BIND_IP`).** A switch on the Connecting card, off by default (Steven, 2026-10-16). On, it sets `BIND_IP` to the address players connect to, and keeps it equal to that address whenever the address changes, picked or detected on Start. Switching it while the server runs asks first, then restarts every service that publishes a port (login, char, map, web, portal). An address change with it on restarts those too, since the address is in every published port. Before each start the app checks that the computer has the address, and if not says so (connect to that network or VPN, pick another address, or switch it off) instead of Docker's bind error halfway through the start. The port clash check binds that address too.

## Leftovers (second PR)

- **A server update moves the images and `.env` together.** An update, a go-back or a Rebuild pulls or builds each image under a staging name (`rag-wrapper/rathena:<PACKETVER>-next`, `rag-wrapper/portal:next`). `compose.yaml` takes its image names from `RATHENA_IMAGE` and `PORTAL_IMAGE`, which default to the stack's names, so the app can point the build at them. Only once every image is ready do they get the stack's names, in the same step that writes the new commit to `.env`, so a cancel can't come between the two. A failed or cancelled pull or build leaves the old images under the stack's names, and the half-made set is removed. A Rebuild works the same way, so it replaces both images or neither.
- **Client patches are streamed.** Each file is compressed straight into the `.thor` file and hashed on the way, so a large file is never held in memory. A failed publish deletes its `.thor.tmp`, and any patch file it already finished, since `plist.txt` doesn't list them yet.
- **Only db-init gets the admin's password.** Only its init step creates the admin account, so `ADMIN_USER` and `ADMIN_PASSWORD` are no longer in the game servers' and web server's environment. After the app blanks the password in `.env`, the stopped db-init container still has it until the next Start recreates it, or Stop removes it. Removing that container sooner would hide the "Database setup: Done" line on the dashboard, so the app leaves it; only docker-group users can inspect containers.
- **Docker Compose 2.24 or newer.** `compose.yaml` uses `!reset`, which older Compose can't read. The Docker check on the main screen reads the version and, below 2.24, says to update the Compose plugin, in the banner other Docker problems use. A version it can't read is let through.
