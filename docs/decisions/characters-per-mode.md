# Characters per game mode

Switching between Pre-Renewal and Renewal keeps each mode's characters apart (PR to come).

- **Accounts are shared; everything else belongs to one mode.** Steven asked for this after it turned out that switching from Renewal to Pre-Renewal makes rAthena turn every third job (and other Renewal-only job) into a Novice on login, and saves it. The `ragnarok` database keeps the tables the login server uses (`login`, `ipbanlist`, `global_acc_reg_num`, `global_acc_reg_str`). Characters, storage, guilds, parties, mail, `#` account variables (including cash points), logs and the web server's tables are in `ragnarok_prere` or `ragnarok_re`. rAthena already reads each server's database from its own setting in `inter_athena.conf`, so the fork needed no change: `entrypoint.sh` points `login_server_db` and `ipban_db` at `ragnarok` and the rest at the mode's database.
- **An existing install's characters stay in the mode it is in.** On the first start with this change, db-init moves every non-account table out of `ragnarok` into the current mode's database in one `RENAME TABLE`, so nothing is copied and it is all or nothing. The other mode starts with no characters the first time it's chosen, with a fresh rAthena schema.
- **Both databases keep every table.** The tables a database doesn't use are left empty. rAthena's upgrade files can touch any table, so each database runs every upgrade file against its own `wrapper_sql_upgrades` record without failing on a missing table.
- **db-init gets the database root password.** Only db-init: creating a mode's database and granting the `ragnarok` account access to it needs root. The game servers and the portal still use the `ragnarok` account.
- **The portal reads accounts from `ragnarok` and characters from the mode's database** (`PRERE`, the same setting the build uses). The desktop app's player list does the same from `.env`.
- **A backup holds all three databases.** A restore drops all three before loading, so it puts back exactly what was there. A backup from before this change only has `ragnarok`; after restoring one, the next start moves its characters into the current mode again.
- **Checked against the real stack** (prebuilt 20250716 images with the new `entrypoint.sh`): an install made with the old layout, with a Pre-Renewal character, moved its tables to `ragnarok_prere` and started; switching to Renewal made an empty `ragnarok_re` and started; switching back brought the character back. The portal's admin page showed the character, its storage and character-name search, and a backup dumped and restored all three databases.

## Review

- **Storage and cash points stay with each mode** (Steven, 2026-10-14). Kafra storage, `#` account variables and `#CASHPOINTS` are in the mode's database, as built. The modes have different item databases, so shared storage would carry items one mode can't use. Only accounts and `##` variables are shared.
- **No copying characters between modes** (Steven, 2026-10-14). A character stays in the mode it was made in. A copy would bring back the Novice reset and Unknown Items this change avoids, so a player who wants the other mode starts a new character there.
