# Mods folder

Roadmap feature 6, custom content: a server-side mods folder that the desktop app switches mods on and off in. PR #17.

- **The mods folder sits in the stack, beside `overrides/` and `patches/`**: `~/.local/share/app.ragwrapper.desktop/stack/mods/`, mounted read-only into every rAthena container as `/rathena/mods`. Like the overrides it's kept across app updates, and people running the stack without the app use the same folder.
- **One folder per mod, with `npc/` and `db/` inside.** Every `.txt` file under `npc/` is a script. `db/*.yml` files are named like rAthena's `db/import/` files (`item_db.yml`, `mob_db.yml`, ...) and written in the same format; `db/pre-re/` and `db/re/` hold files for one game mode only. Folder names are limited to letters, digits, `.`, `_` and `-`, since they end up in config and YAML files.
- **`mods/enabled.txt` says which mods are on**, one name per line. The Mods screen rewrites it; people without the app edit it by hand.
- **Mods load in the order of `enabled.txt`, and the later one wins.** When two mods change the same database entry, rAthena applies both in order, so the later mod's fields win. The Mods screen lists the mods that are on in that order, with arrows to move each one up or down; a mod switched on goes to the end. This settles the roadmap's open load-order question (see the review answer below).
- **Scripts load after rAthena's own, through `npc/scripts_custom.conf`.** The entrypoint writes `npc/mods.conf` and adds one import line for it to `npc/scripts_custom.conf` in the container. Listing the scripts in `map_conf.txt` instead would load them before rAthena's scripts and lose them on `@reloadscript`.
- **Database files load as `Footer` imports of the `db/import/` files.** On every start the entrypoint copies rAthena's `db/import-tmpl/*.yml` back over `db/import/` and appends the enabled mods' files as imports, so a mod switched off leaves nothing behind. rAthena reads them after its own entries and `db/import`. A file in `db/` with any other name is skipped with a warning in the log.
- **Errors show under the mod, from the map server's log.** The screen picks out rAthena's `[Error]` and `[Warning]` messages that name a file under `mods/<name>/`, with a script error's code excerpt and a database error's file and line. This settles the roadmap's open question on how errors are shown.
- **Changes wait for a restart, and the screen says which.** After each Start or restart from the app, `mods/.applied.json` records the enabled mods and a checksum of their files' names, sizes and times. While the game servers run, a mod switched on or off, or with changed files, since then is marked "loads on restart" or "unloads on restart", and the screen offers **Restart game servers**.
- **The database is backed up before a mod's database files first load**, as the roadmap asked: when a Start or restart brings in an enabled mod whose `db/` files are new or changed since the last start, it makes an automatic backup ("Before loading a mod's database files") first. Scripts alone don't trigger one.
- **The portal's item names include mod items.** `db-init` adds the enabled mods' `item_db.yml` to the item names it loads, on the next full Start.
- **Existing installs need a Rebuild before mods load.** The entrypoint is part of the rAthena image, so an image built before this change ignores `mods/`. New installs build it with the image.
- **Checked against a real rAthena build** (the fork's `rag-wrapper` branch, pre-renewal, 20250716): an enabled mod's NPC loaded, its `item_db.yml` added an item and renamed Red Potion (in the map server and in the portal's item names), its `pre-re/mob_db.yml` loaded, and a broken mod's script and database errors were picked out of the map server's log under that mod.
- **No fork change.** Everything is in the stack's entrypoint; rAthena's own YAML imports and script imports do the loading.

Questions asked about the finished feature (PR #17), one at a time.

- **The mods folder stays in the stack folder**, `~/.local/share/app.ragwrapper.desktop/stack/mods/`, beside `overrides/` and `patches/`, rather than in the app's data folder beside `client-files/`. Compose mounts it with a relative path, and the stack run without the app uses the same folder.
- **The load order is set with arrows on the Mods screen**, not by folder names. The first build loaded mods alphabetically and had people rename folders (`10-`, `20-`) to reorder; now `enabled.txt` keeps the order and the screen's up and down arrows change it. A new order waits for a restart like any other change.
