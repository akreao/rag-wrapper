# Playing on Linux

A "Playing on Linux" section on the portal's How to connect page, and a launcher script players can download. Built in the PR that added this file.

- **Wine with DXVK, not Proton.** It's the setup that works for Steven (2026-10-15): DXVK runs the client's DirectX 9 renderer on Vulkan and "greatly improved" performance over plain Wine. Under Proton the client loads, then quits before opening a window, with or without DXVK, so the page tells players to use plain Wine and doesn't try to explain Proton.
- **DirectX 9 in OpenSetup.** The client has both a DirectX 7 and a DirectX 9 renderer, picked in OpenSetup and saved in `savedata/OptionInfo.lua`. DXVK only helps DirectX 9.
- **Frame cap in a DXVK config file.** The `DXVK_FRAME_RATE` variable didn't cap the frame rate for Steven; `d3d9.maxFrameRate = 60` in a file passed as `DXVK_CONFIG_FILE` did. The launcher writes `~/.config/dxvk-ro.conf` on its first run and never overwrites it, so a player's own cap stays. The file sits outside the client folder, so the patcher never sees it.
- **The launcher is one bash script, the same for every server** (`portal/clientfiles/play-on-linux.sh`, served at `/connect/play-on-linux.sh`). It goes in the client folder and starts from there, because the client finds its GRFs from the folder it starts in. It makes its own Wine prefix (`~/.local/share/rag-wrapper-wine`, or `WINEPREFIX`) so the game's DLL overrides don't touch a player's other Wine programs, installs DXVK once with `winetricks -q dxvk`, and starts the patcher (`rag-wrapper-patcher.exe`, falling back to `rag-wrapper.exe`). `setup` opens OpenSetup and `run` starts any other Windows program in the same prefix, such as WARPGATE. `RO_DXVK=0` forces Wine's own d3d9 for drivers without Vulkan.
- **Players are told to run it with `bash`.** A downloaded file loses its execute bit, and `bash play-on-linux.sh` works without `chmod`.
- **The new patcher on Linux.** rpatchur shows its page in Internet Explorer's engine; ours draws plain Win32 controls and was checked under Wine. While both are offered, the Linux section points players at the new one. (Since 2026-10-23 the launcher is the main download, so the Linux steps no longer point anywhere else; [launcher.md](launcher.md).)
- **Not checked by a Linux player other than Steven.** WARPGATE under Wine is untested, so the page says to copy a client folder made on a Windows PC if WARPGATE won't run. The script was tested here against stand-in `wine` and `winetricks` commands and passes shellcheck (in CI), not against a real client.
- **OpenSetup on the first run in a prefix (Steven, 2026-10-16).** With the launcher's new prefix the client ran but never showed its window, as it did under Proton. Saving OpenSetup again in that prefix fixed it, even though OpenSetup already showed his choices: `OptionInfo.lua` names the graphics card as the prefix that saved it saw it, and in another prefix the client doesn't find it. The launcher now opens OpenSetup before the first game in each prefix (marker `.rag-wrapper-setup`), and `setup` sets the same marker (since moved to the client folder, below). Proton's missing window was very likely the same cause.
- **Core fonts in the prefix (Steven, 2026-10-16).** A new prefix lacks Microsoft's core fonts, so the launcher installs them once with `winetricks -q corefonts` (marker `.rag-wrapper-corefonts`).
- **The fonts never stop the game (pre-release audit, 2026-10-16).** winetricks downloads the fonts and unpacks them with `cabextract`, so a PC without internet or without cabextract couldn't install them, and the launcher used to stop there on every run. Now a failed or impossible fonts install (winetricks missing too) prints a warning and the game starts; no marker is written, so the next run tries again. `RO_FONTS=0` skips the fonts, like `RO_DXVK=0` skips DXVK. winetricks is only required for DXVK, so `RO_DXVK=0` without winetricks still plays.
- **The OpenSetup marker lives in the client folder (pre-release audit, 2026-10-16).** `OptionInfo.lua` is in the client folder, so a per-prefix marker missed a new or copied client folder in front of a prefix that had already played. The marker `.rag-wrapper-setup` is now in the client folder and holds the prefix path, the prefix's creation time (`.rag-wrapper-made` in the prefix, so a remade prefix at the same path counts as new) and whether DXVK is on, since Wine's Direct3D and DXVK may report the graphics card differently. OpenSetup opens again whenever any of these differ. Players who already played see OpenSetup once more after this change.
