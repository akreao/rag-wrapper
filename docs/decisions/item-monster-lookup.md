# Item and monster lookup in the portal

Public Items and Monsters pages in the portal (roadmap feature 27). Built in the PR that adds this file.

- **Open to everyone, no log-in.** `/items` and `/monsters` are in the portal's top bar after Rankings and Market. Search items by name, AegisName or number with a type filter; monsters by name, AegisName or number, with an "On maps" box to hide monsters that never spawn by themselves. 50 per page.
- **An item's page:** number, type, weight, buy and sell price, the equipment stats that apply (attack, defense, slots, required level, jobs, where it's worn), its effect script, and the monsters that drop it, best chance first. The in-game description isn't on the server (it's in the client's itemInfo), so the script stands in for it.
- **A monster's page:** stats, race, element, size, exp, its drops (MVP prizes first) and the maps it spawns on, with how many and, when it isn't the usual few seconds, the respawn time (an MVP's "1 hour to 1 hour 10 minutes").
- **Read from what the map server loads, not a copy.** `docker/rathena/lookup_db.py` reads `db/item_db.yml`, `db/mob_db.yml` and `db/mob_item_ratio.yml` and follows their Footer imports the way rAthena does (the mode's files, then db/import, then the enabled mods' files), applying later entries as partial updates (with `Modes`, `RaceGroups` and `Locations` changed key by key and `Ai` resetting `Modes`, as rAthena does), Header `Clear`, and Drops with and without an `Index`. Spawns come from the `monster` and `boss_monster` lines of the NPC files `npc/<mode>/scripts_main.conf` loads, following `import:`, `npc:` and `delnpc:`, so rAthena's custom NPCs and the mods' scripts count. Commented-out `//` spawn lines don't. Monsters that only come from scripts (events, quests, summons, boxes) have no map listed.
- **Drop chances and exp are this server's.** The script applies the battle config the map server reads (`conf/battle_athena.conf` with the overrides folder's `battle_conf.txt`): the `item_rate_*` setting for the item's type and the monster's kind (normal, boss, MVP, treasure chest), the min/max caps, logarithmic drops, `drop_rateincrease`, `mob_item_ratio.yml`, `base_exp_rate`/`job_exp_rate`/`mvp_exp_rate` and `mob_count_rate`, as `mob.cpp` and `npc.cpp` do. Renewal's level penalty depends on the player, so pages say chances are before it. Respawn times are shown as the spawn line writes them (`mob_spawn_delay` and `boss_spawn_delay` aren't applied).
- **Filled when the map server starts, beside it.** The map service's entrypoint runs the script in the background and then starts the map server, so a restart after switching a mod or changing rates (which only restarts the game servers, not `db-init`) refreshes the pages too. A Renewal load takes about 10 seconds; until the first one finishes the pages say the lists are still filling in. It runs under `nice`, and is skipped when nothing it reads has changed (see below).
- **Swapped in whole.** The script fills `*_new` tables and renames all five into place in one statement, so the portal never shows a half-filled list and keeps the previous data if a load fails. A failure is a `[Warning]` in the map server's log and never stops the map server.
- **Five tables in each mode's characters database:** `wrapper_items`, `wrapper_mobs`, `wrapper_mob_drops`, `wrapper_mob_spawns` and `wrapper_lookup_info` (load time and rates). They're rebuilt from files, so they aren't in `sql-files` and need no upgrade file. `wrapper_items` replaces `wrapper_item_names`, which `db-init` used to fill for the admin pages' item names; the script drops the old table.
- **Custom items and monsters are marked** with the mod that added them ("Mod: eden-rework"), or "Custom" for `db/import`.
- **Skipped when its inputs haven't changed.** `entrypoint.sh` hashes the game mode, `lookup_db.py` itself and the contents of every file under `db/`, `conf/` (with the overrides folder), `npc/` and the mods' `db/` and `npc/` folders, and lookup_db.py stores the hash in `wrapper_lookup_info` (`inputs`) with the tables it swaps in. A start with the same hash only sets `loaded_at` to now. It's deliberately wider than what the script reads: a file that doesn't matter costs one load, never stale pages. A new or reset database has no table, an older image stores no hash, and a failure to work out the hash leaves it empty, so all of those load. Hashing takes well under a second.
- **Loaded as utf8mb4.** The mysql client gets `--default-character-set=utf8mb4` for this load only. Without it the container (no locale) sends as latin1 and names such as "Old King’s Crown" are stored garbled. rAthena's own schema and upgrade imports are ASCII and keep the client's default, so their behaviour doesn't change.
