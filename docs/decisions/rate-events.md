# EXP and drop events

Roadmap feature 28: pick EXP and drop rates and a time window in the desktop app ("double EXP this weekend"), applied without a restart. Built in the PR that adds this file.

- **rAthena changes the rates live; no fork change.** Checked on a real map server: the script command `setbattleflag "<flag>", <value>, 1` sets the battle config and, for the exp and drop flags, reloads the monster database (`mob_reload`), which is where rAthena multiplies each monster's exp and drop chances. A Poring's base exp went from 2 to 6 at 300% and its Jellopy from 70% to 100% (capped by `item_drop_common_max`), and back when the event ended.
- **An NPC script in the stack applies the events** (`docker/rathena/npc/rate_events.txt`, copied to `npc/wrapper/` in the image and loaded by entrypoint.sh after rAthena's scripts). Every 30 seconds it reads the event that's on from `wrapper_rate_events` and sets the rates, so an event starts and ends within half a minute of its time, whether or not the desktop app is open. The map server's console isn't reachable in Docker, and a script needs no rAthena change.
- **Rates are a percent of the server's own**, so an event works the same whatever the battle config says: 200% doubles them. EXP covers base and job exp; drops cover every `item_rate_*` group (common, healing, usable, equipment, cards, each for normal, boss and MVP monsters, plus MVP prizes and treasure chests). Each stops at rAthena's limit for the flag.
- **The server's own rates are what the map server read at start-up.** The script keeps what it set in permanent `$` variables, so `@reloadscript` (which keeps the rates but clears temporary variables) doesn't double them; a fresh start (`OnInterIfInitOnce`) reads the config again. A flag that isn't what the script set, after `@reloadbattleconf` say, becomes the new own rate.
- **Kept in the database, not the overrides folder**, because the map server has to read it while running. The table is in the characters database of the game mode, made by db-init like `wrapper_item_names`, so each mode has its own events. The screen needs the server running and says so otherwise.
- **One event at a time**: the screen refuses one that overlaps another, so there's no question of which rates win. Back-to-back events are fine. To change one, delete it and plan it again.
- **Announced in game** with `announce` when it starts (once, even across restarts: the script marks it `started`) and when it ends or is deleted early. Players who log in during one get the start line in their chat. The lines are written by the app in local time ("Double EXP weekend: EXP x2 until Sun 18 Oct 23:59."), since the server's clock in Docker is UTC.
- **Names are plain ASCII**: the game client shows announcements in its own code page, so accented letters would come out garbled. Up to 60 characters.
- **An optional News post** (on by default) goes on top of the News page, dated like the News screen's own posts.
- **Events stack on rAthena's Floating Rates NPC** (Steven, 2026-10-16): with that custom NPC on, an event multiplies whatever rates it last set, so double EXP over a floating 130% gives 260%. The script treats a rate another script changed as the server's own, so after Floating Rates' hourly change the event applies on top within 30 seconds.
- **Restart warnings (feature 25) are separate**: that feature's announcements don't depend on this one.
