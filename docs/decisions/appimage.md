# AppImage

Packaging the desktop app as an AppImage (roadmap feature 9, first half; prebuilt server images come later).

- **The app ships as one AppImage, and nothing else.** `tauri.conf.json` builds only the `appimage` target; the `.deb` target is gone, as the roadmap decided (no .deb or Flatpak). The rAthena image is still built locally on first start, as before.
- **Merging a version bump is the release.** On each push to `main`, the Release workflow checks whether the app's version (`tauri.conf.json`, which must match `Cargo.toml`) already has a GitHub release; if not, it builds `rag-wrapper-<version>-x86_64.AppImage` and publishes release `v<version>`, creating the tag itself. Nobody pushes tags: Claude's cloud sessions can only push to their own branch, so a tag-triggered release (the first design) needed Steven at a terminal for every release. It's published straight away, not kept as a draft: the version bump PR is already reviewed and approved, and Steven is the only one installing it.
- **Release notes are a file in the version bump PR.** `docs/releases/<version>.md` leads the release, followed by the pinned rAthena commit, the requirements and GitHub's list of merged PRs, so the notes are reviewed with the version change. A version without a file is released with just the generated part.
- **It's built on Ubuntu 22.04.** An AppImage needs a glibc at least as new as the one it was built with, so building on the oldest supported runner lets it run on older distributions as well as Steven's.
- **Pull requests that touch the packaging build it too.** A change to the workflow, `tauri.conf.json`, `Cargo.toml`, `Cargo.lock` or the release notes builds the AppImage, checks it holds the stack files, and keeps it as a workflow artifact for 14 days. It isn't a required check, so its job name can change; the required "Desktop app (Rust)" job still runs the compile checks and tests on every PR.
- **Programs the app starts don't see the AppImage's libraries.** The AppImage's launcher sets `LD_LIBRARY_PATH`, `XDG_DATA_DIRS`, GTK's module paths and more to point inside it; a browser or file manager started with them can load the wrong GTK and fail. `src/host.rs` takes those entries out for `docker` and for `xdg-open` (opening folders and web pages), so they get the user's own environment. This replaced Tauri's opener plugin, which passes the environment on unchanged.
- **New versions are found by hand.** The app doesn't check GitHub for a newer AppImage or update itself, so it makes no internet calls of its own; Steven tags the releases, so he knows when one is out, and swaps the file himself.
- **The AppImage adds itself to the applications menu.** On every launch from the AppImage, the app writes `~/.local/share/applications/app.ragwrapper.desktop.desktop` pointing at the AppImage's current path, with its icon copied into the app's data folder, so the entry keeps working after the file is moved or replaced by a newer version. Deleting the AppImage leaves the entry behind until it's deleted by hand.
- **The first release is v0.1.0.** The app's version stays 0.1.0, since it hasn't run on Steven's desktop yet; it's published when the change to version-bump releases merges, with notes in `docs/releases/0.1.0.md`.
- **The user needs Docker with the Compose plugin, and FUSE 2.** The AppImage doesn't carry Docker. FUSE 2 is `libfuse2` (`libfuse2t64` on Ubuntu 24.04); without it, `--appimage-extract-and-run` works.
