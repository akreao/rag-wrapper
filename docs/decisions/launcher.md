# The launcher

Our patcher (`portal/cmd/patcher`, [own-patcher.md](own-patcher.md)) becomes a tabbed launcher in the portal's look. Asked for by Steven on 2026-10-23: get the players' launcher away from Internet Explorer (rpatchur's window), with more features, tabs and the portal's theme ([portal-redesign.md](portal-redesign.md)).

- **It's our patcher, grown.** Same exe name (`rag-wrapper-patcher.exe`), same config, cache and signed `info.json`, same self-update, so players who have the new patcher get the launcher with their next start, without a download. Patching itself didn't change.
- **Gio draws the window** ([gioui.org](https://gioui.org), pure Go, no cgo, cross-compiled like before). Steven picked it over WebView2 (needs Edge's runtime, works badly under Wine) and themed Win32 controls (old look, everything hand-drawn). It draws with Direct3D 11. (Gio's OpenGL renderer needs ANGLE's `libEGL.dll`, which the download doesn't ship, so on Windows Direct3D 11 is the only one that works.)
- **Gio stays at v0.8.0.** Gio v0.9 and later read the mouse only through `WM_POINTER` messages and call `RegisterTouchWindow` / `EnableMouseInPointer`, which Wine 9 doesn't implement, so the window never opens there (Wine's development versions have them). v0.8.0 opens, draws and takes clicks under Wine 9. It needs `github.com/go-text/typesetting` v0.2.1; with a newer one every letter draws as a box. Check a newer Gio under Wine 9 before moving either.
- **The portal's look.** Its colour tokens (light and dark), Nunito, raised panels with a blue title bar and three window dots, pink Play button, blue tabs, the poring logo drawn from `poring.svg`. Nunito is the portal's variable font cut into 400, 700 and 800 TTFs (`cmd/patcher/fonts/`; Gio can't read WOFF2), with its OFL licence.
- **Four tabs.** Play: the server at a glance (game server up, playing now, mode, client date), the newest news post and buttons for the portal's pages. News: every post. Players: who's online (name, job, levels, map) and the top adventurers. Settings: the client's settings program, Check game files, the game and screenshot folders, Keep the launcher open after Play, and the theme. Status, progress, Try again and Play sit under every tab.
- **The server at a glance comes from `/patcher/launcher.json`**, a new portal page: server name, mode, client date, address and login port, online count, up to 100 online and the top 10 characters (admins' left out, as on Rankings), the 10 newest news posts as plain text, and the portal's page links. It isn't signed and nothing in it changes the client; links that don't point at the portal are dropped. The launcher fetches it at start and every 30 seconds.
- **"Game server" means the login server answers from this PC.** The launcher opens a TCP connection to the address and login port the client uses, so it says Offline when the game would fail to connect, even if the portal answers.
- **When the portal doesn't answer, Game server says Unknown, not Offline** (pre-release audit, 2026-10-23). The launcher still tries the address and port from the portal's last answer, and says Online if they take the connection; otherwise it can't tell, since the portal restarting says nothing about the game. The Play tab then says the website isn't answering and Play may still work.
- **Check game files rebuilds `rag-wrapper.grf` from scratch.** It deletes that GRF, sets the last applied patch to 0 and patches again, so every patch applies in order. It asks first, since it downloads everything again. `data.grf` and other files are left alone.
- **Settings live in `rag-wrapper-launcher.json`** beside the exe: keep open after Play, theme (Match Windows, Light, Dark; Match Windows reads `AppsUseLightTheme`), the last tab and the server's name (shown until the server answers). Patches can't overwrite it.
- **Errors show in the window, not in boxes.** A failed Play, Settings or folder button says why on the status line. Only the checks before the window opens (missing config, no `data.grf`) and a window that can't draw still use message boxes.
- **A window that can't draw says so, and points to the old patcher** (pre-release audit, 2026-10-23). Before opening the window the launcher creates and drops a Direct3D 11 device, as Gio will; if that fails (no graphics driver, a very old card, a virtual machine without 3D), or Gio later closes the window with an error, a message box names the error and sends the player to the How to connect page's "download the old patcher" link, and the launcher exits with code 1. The check comes first because Gio's own failure isn't clean: after Direct3D 11 fails it tries OpenGL, and the second time round its loader crashes on the missing `libEGL.dll`, so the launcher vanished without a word (seen under Wine with `renderer=no3d`). A failure after the window opened (a lost device whose new one fails) would reach the same crash. The portal's Dockerfile builds it with `-tags noopengl`, which leaves the OpenGL fallback out, so that case reaches the message box too.
- **The window fits the screen** (pre-release audit, 2026-10-23). It opens at 980×660 dp, or smaller when the main screen's work area (the screen less the taskbar, at its scaling) can't hold that with the window's frame, and centred in the work area of the screen it opens on. The smallest size is 860×440 dp, shrunk the same way. Below 440 dp of room the Play and Settings tabs scroll, so the status line and Play always show; News and Players are lists that scroll anyway. 768p at 125% and 1080p at 150% used to open with Play cut off or behind the taskbar.
- **Text in any script draws** (pre-release audit, 2026-10-23). Nunito comes first, then Segoe UI, then whichever Windows font has the letter, so Polish, Turkish, Cyrillic, Greek, CJK and emoji in news posts and character names don't draw as boxes (the embedded Nunito has Latin-1 only). Reading `C:\Windows\Fonts` takes a moment the first time (go-text keeps an index in the user's cache folder), so the window opens with Nunito alone and swaps in the shaper with the system fonts when it's ready.
- **After a self-update the old launcher closes even while minimized** (pre-release audit, 2026-10-23). It posts itself WM_CLOSE from the patch goroutine; Gio draws no frames for a minimized window, so waiting for the next frame left it running beside the new one.
- **Licences.** The image collects Gio's, go-text's, `golang.org/x/*`'s and Nunito's licences into `LICENSE-third-party`, which goes in the download as `licenses/third-party-LICENSES.txt` beside Go's.
- **The launcher is the main download** (Steven, 2026-10-23, in the review). The How to connect page's button gets the launcher, with rpatchur as a small "download the old patcher" link for a PC where it won't start. Dropping rpatchur still waits for a player's Windows PC ([own-patcher.md](own-patcher.md)). The download URLs didn't change. In the Linux steps, `play-on-linux.sh` is now called "the script", so "the launcher" always means the Windows program.
- **Checked under Wine 9** (Xvfb, llvmpipe): every tab in light and dark, patching four test patches with progress, Try again after the portal was down, Check game files, Play starting the client and closing the launcher, and self-update.

Questions asked about the finished launcher (PR #97), one at a time.

- **The launcher is the main download now**, not after a Windows test (see above).
- **Play closes the launcher by default**, as the patchers always did. Players who want it left open turn on "Keep the launcher open after Play" in Settings. Left open behind the game, it would keep asking the server who's online every 30 seconds for nothing.
