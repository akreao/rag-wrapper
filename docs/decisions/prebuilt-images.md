# Prebuilt images

Roadmap feature 9, second half: the desktop app downloads the rAthena and portal images instead of compiling them. Replaces "build the image locally" from [plan.md](plan.md) as the default, keeping the local build as the fallback.

- **CI publishes, the app pulls.** `.github/workflows/images.yml` builds and pushes the images to GHCR (`ghcr.io/akreao/rag-wrapper-rathena`, `ghcr.io/akreao/rag-wrapper-portal`) on every push to `main` that touches `docker/rathena/`, `portal/` or `.env.example`, and on demand. The app pulls the matching image and tags it with the local name Compose already uses, so `compose.yaml`, "Restart on the new version" and the mods screen's checks work unchanged.
- **Which rAthena images.** The commit pinned in `.env.example`, for both PACKETVER presets (20250716 and 20220406) in both Pre-Renewal and Renewal: four images per pin. Chosen over publishing only the default so no setting on the Settings screen means a 10-minute compile; CI minutes are free on a public repository. PACKETVER and mode are compiled in, so each combination is its own image; the app picks by the settings in `.env`.
- **The tag names everything the image was built from.** `rag-wrapper-rathena:<PACKETVER>-<prere|re>-<first 12 of the commit>-<hash>` and `rag-wrapper-portal:<hash>`. The hash covers the files in `docker/rathena/` or `portal/` (dotfiles aside, since the app's bundle skips them), computed the same way by the workflow and by the app from the copy it ships, so a new entrypoint (as the mods folder needed) or new portal code never pulls an old image. A test checks the app's hash matches the workflow's shell pipeline.
- **Local build stays the fallback.** Anything without a published image builds as before: another PACKETVER, a commit set by hand to test a fork change, a different `RATHENA_REPO`, no network, a non-x86-64 machine. Each image falls back on its own, so a published rAthena image with an unpublished portal pulls one and builds the other. `PREBUILT_IMAGES=` (empty) in `.env` turns downloads off; a missing key uses the app's default, so existing installs get prebuilt images without editing `.env`.
- **When the app pulls.** Start pulls only images that aren't on the machine yet (the first start, or after a PACKETVER change). Rebuild, saving a build setting and Update server always pull (or build). The server update's ask-first flow is unchanged: the update downloads instead of compiling, then pins.
- **Published images are skipped.** A tag that already exists in the registry isn't rebuilt, so a push to `main` that doesn't change what goes into an image costs a manifest check. A PR that changes the workflow builds all five without publishing.
- **The app's stack copy of `docker/` and `portal/` is replaced whole** on each app start, so a file an older app version shipped can't linger in a build or change the hash.
- **Licence.** rAthena is GPL-3.0; each image is labelled with the source repository and the exact commit it was built from, both public.
- **Package visibility.** New GHCR packages may start private. After the first publish, both packages must be set to public in their package settings, or every pull fails and the app quietly builds locally.
