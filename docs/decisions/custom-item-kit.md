# Custom item kit

Roadmap feature 16: a template mod with both halves of a custom item and a guide, so a new item starts from files in the right places. Asked for by Steven on 2026-10-15, after mods could carry client files ([mods-client-files.md](mods-client-files.md)).

- **A mod's item names go in `SystemEN/itemInfo_C.lua`, in `tbl_custom`.** The open question was that a mod's itemInfo would replace the players' whole item list, since the base translation isn't distributed ([publish-client-patch.md](publish-client-patch.md)). Steven pointed out that llchrisll's English translation provides `itemInfo_C.lua` for custom items. Checked in his client (2026-10-15): the patched exe reads `SystemEN/iteminfo.lua`; that file loads the full list from `SystemEN/LuaFiles514/itemInfo.lua`, then `dofile`s `SystemEN/itemInfo_C.lua` and merges its `tbl_custom` (only Ids the list lacks) and `tbl_override` (replacing official entries) into it. The translation's own `itemInfo_C.lua` has both tables empty, so the patch replacing it loses nothing, and the file is the server's own content, safe to distribute. Steven's eden-rework mod already uses the same `_C` pattern for quests.
- **Custom items take Ids 40000 to 49999.** None are used in rAthena's item databases (pre-re and re) or in the translation's item list (26,793 items, checked 2026-10-15), and they stay under 65535 for older clients.
- **The template reuses existing looks.** The Kit Potion uses the Red Potion's sprite and icon and the Kit Ribbon the Ribbon's (`View` and `ClassNum` 17), so the mod works with no sprite files, and the app ships none of Gravity's art. The Korean resource names are written as Lua byte escapes (`"\184\174\186\187"`), so the file is plain ASCII and still gives the client CP949 bytes. The template's `README.md` says where a new look's sprite, icon and description picture go.
- **A new headgear look is out of the template's reach.** It needs entries in `accessoryid.lub` and `accname.lub`, which ship compiled inside `data.grf`, and compiled lub can't be merged ([mods-client-files.md](mods-client-files.md)). The guide says so; reusing an existing `View` needs neither file.
- **The template ships inside the app.** It's compiled into the desktop app (`desktop/src-tauri/item-mod/`, `itemkit.rs`), not kept in `mods/`, so it isn't listed as a mod. The Mods screen's New item mod button copies it into `mods/<name>/`, switched off, and opens the folder.
- **The Mods screen checks each mod's custom items.** It lists an item in the custom range in the mod's `item_db.yml` with no `tbl_custom` entry in its client files, a `tbl_custom` entry with no `item_db.yml` entry, and any other itemInfo file, which would replace the players' list or not be read. The check is per mod, as one mod is meant to carry both halves, and only for the custom range, since a mod changing an official item's price needs no client entry.
- **Checked on real files.** The template loaded in a local build of the pinned rAthena commit (Pre-Renewal, 20250716) with no errors or warnings: 2 items from the mod's `item_db.yml`, the shop among the NPCs. The template's `itemInfo_C.lua` loaded in Lua 5.1 the translation's way and gave the right CP949 sprite names.
