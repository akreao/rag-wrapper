# Test coverage

Tests added after the 0.3.0 features, where a break would go unnoticed until a player hit it (PR #43).

- **What was covered before.** The portal's Go tests, `merge_mods.py`'s tests and the desktop app's unit tests (settings and battle config overrides, mods screen, images, backups, client patch) ran in CI. `entrypoint.sh` had only `shellcheck`, the desktop app's first-run `.env` writing and app-update install had no tests, and nothing started the stack.
- **`entrypoint.sh` is tested on a copy of rAthena's folders.** `docker/rathena/test_entrypoint.py` runs the script with `config`, a command that writes the configs, loads the mods and stops, and `RATHENA_DIR` points it at a temporary folder. It covers the stack's values winning over the overrides folder, a database per game mode, `enabled.txt` parsing, script and database loading order, text databases, switching a mod off, and that the files it loads are the ones `merge_mods.py --check` checks for the Mods screen. It runs in the Compose stack job.
- **The desktop app's `.env` setup and stack install have tests.** First-run setup's changes moved into `write_setup`, which tests call with a temporary `.env`; `stack::install` is tested for keeping `.env`, overrides, mods and patches across an app update.
- **A new CI job, Stack smoke test, starts the whole stack.** It uses the published images when the PR doesn't change `docker/rathena/` or `portal/`, and builds them otherwise. With the sample mod in `.github/smoke/mods/smoke-test/` switched on, `.github/smoke/check.py` registers an account on the portal, logs in to the login server with it and with the first-run admin over the game client's protocol, enters the char server, checks a wrong password is refused, and checks the map server loaded the mod's script and item. It runs on every PR.
- **The smoke test runs in both game modes.** A second job, Stack smoke test (Renewal), runs it with `PRERE=no`: Renewal has its own image and characters database, and Steven runs Renewal-only mods.
